# Security Policy

## Supported versions

Security fixes are provided for the latest published release.

## Reporting a vulnerability

Do not open a public issue for an unpatched vulnerability. Use GitHub's **Security → Report a vulnerability** form so the report can be discussed privately. Include the affected version, operating system, reproduction steps, impact, and any proof-of-concept files needed to reproduce the issue.

The project processes untrusted torrent metadata and peer traffic. Reports involving path traversal, unsafe file replacement, protocol parsing, local data exposure, or remote denial of service are especially useful.

Do not include copyrighted payload data, credentials, or personal information in a report.
